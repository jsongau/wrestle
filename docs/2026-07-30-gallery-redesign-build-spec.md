# Sticky Media Sub-Nav — design, markup, CSS, integration

## 1. The decisive fact I verified (drives everything)

The mega nav is **not `position:fixed`** — `css/site.css:115` sets `.site-header{position:sticky;top:0;z-index:100}`. The header is a single sticky block containing two stacked pieces:

| Piece | Rule | Height |
|---|---|---|
| Ticker `.rt` | `site.css:3045` `height:40px` + `border-bottom:1px` | 41px |
| Nav bar `.nav7 .bar` | `site.css:1333` `min-height:62px` | 62px |
| `.site-header` own `border-bottom:1px` | `site.css:116` | 1px |

**Combined sticky footprint = 40 + 1 + 62 = 103px** (104 including the header's bottom border). This is stable across breakpoints: the ticker stays 40px on mobile (only `.rt-dots`/`.rt-more` hide, `site.css:3064-3065`), the bar stays 62px (tabs horizontally scroll rather than wrap, `site.css:1778`), and `is-stuck` only adds a shadow, no height change. So a **single constant `top` value is safe everywhere.** The existing `[id]{scroll-margin-top:112px}` (`site.css:798`) confirms ~104px header.

Because the header is *sticky* (in normal flow), a later sibling with `position:sticky;top:103px` pins flush beneath it with **no offset math and no JS** — this is why sticky (not fixed) is the whole game.

## 2. Recommendation: section-scoped, generated by build_gallery.py — NOT a site-wide stamp

The shell contract itself resolves this: *"anything site-wide must be a component that gets stamped; anything section-scoped should be generated by build_gallery.py into the pages it owns."*

This bar is **section-scoped**, so it belongs in the generator. Justification:
- The mega nav already gives global 7-tab navigation on every page. A second bar stamped site-wide would be redundant chrome, eat ~42px on every wrestler/title/event page, and fight the "fixed 7-tab instrument, never grow the bar" philosophy.
- Every link (This Week, Archive, Shows, By Promotion, Moments, Interviews) is a *media-surface* destination. On a belt-lineage or dossier page it is noise.
- Streaming precedent (Max/Netflix) scopes these strips to a content hub, not globally.
- Placing it as the first node **inside `<main>`** (which build_gallery owns) means the stamped `<header>` stub is never touched — contract intact.

## 3. Link set + active-state logic

Six links, all real URLs, resolved server-side (the generator writes `aria-current="page"` — zero JS, works with no-JS, best a11y):

| Label | href | Active when page path… |
|---|---|---|
| This Week | `/gallery/<latest-week>/` | matches `/gallery/YYYY-MM-DD/` **or** `/media/w/*` (a weekly clip) |
| Archive | `/gallery/` | equals `/gallery/` exactly |
| Shows | `/media/` | equals `/media/` exactly |
| By Promotion | `/promotions/` | starts with `/promotions/` |
| Moments | `/moments/` | starts with `/moments/` |
| Interviews | `/media/interviews/` | starts with `/media/interviews/` |

Precedence: match most-specific first. `/media/interviews/` is a **prefix** match while Shows `/media/` is **exact-only**, so a video page or the interviews page never double-activates. Exactly one link carries `aria-current` per page.

**Stacking spec, precisely:** header `z-index:100` establishes a stacking context; every header descendant — including the mega dropdown panels (`.mega7`, `z-index:60`, `site.css:1381`) — renders *inside* that context, so the whole header subtree sits above the sub-nav's separate context at `z-index:90`. Result: when a mega panel opens it overlays the sub-nav correctly, and any sub-pixel overlap resolves in the header's favor. The theater modal (`z-index:200`) stays above all. No z-index bug.

**Mobile:** `flex-wrap:nowrap` + `overflow-x:auto` + hidden scrollbar + a right-edge mask fade to hint more items. No wrap, no height change, `top` unchanged.

**A11y:** `<nav aria-label>` + list semantics; single `aria-current="page"`; links use the global `:focus-visible` outline (`site.css:40`); it is a link list, not a widget, so Tab (not arrow-roving) is the correct model and nothing traps focus.

# Build-integration spec: `/gallery/<Monday>/` for Google + GEO, compounding through the week

## 0. What's wrong today (baseline, verified in `build_gallery.py`)

| Surface | Current | Problem |
|---|---|---|
| `week_page()` head | `shell(title, desc, canonical, main)` | no JSON-LD, no OG/Twitter, no `robots`, no prev/next |
| H1 | none; `<h2>` in `.section-head` | page has no H1; H1 lives only in JS-rendered proto |
| Title | `"Week of July 27, 2026 — Viewing Gallery \| Wrestle Lore"` | em-dash separator (banned); zero promotion/show/"highlights"/"results" keywords |
| Meta desc | identical template every week except the label | thin/duplicate risk; no show names, no dates, no streaming keywords |
| Body copy | one fixed `tw-lede` string, byte-identical across all 6 weeks | duplicate-content risk; nothing crawlable about *what aired* |
| Growth | page only changes as `WEEKS[0]` gains clips | no lastmod bump, no "still to come" scaffold, so early-week page reads thin |

Everything below is expressed as concrete emissions from `build_gallery.py` off the existing `WEEKS` / `INDEX` model.

## 0.1 New per-week derived object (compute once, feed everything)

Add a helper that every emitter reads from, so head tags, copy, JSON-LD, sitemap and llms.txt never drift:

```python
def week_meta(wk):
    start = wk["start"]; end = start + datetime.timedelta(days=6)
    present = [p for p in ORDER if wk["promos"].get(p)]          # promotions with clips
    shows = []                                                    # [(promo, show, date, [clips])]
    for p in present:
        byshow = {}
        for (y,d,l) in wk["promos"][p]:
            s = l.split("·")[0].strip()
            byshow.setdefault((s,d), []).append((y,d,l))
        for (s,d), clips in byshow.items():
            shows.append((p, s, d, clips))
    shows.sort(key=lambda t: t[2])                                # chronological
    nclips = sum(len(v) for v in wk["promos"].values())
    ples = [(dt,co,ev,note) for dt,(co,ev,note) in SPECIALS.items() if start <= dt <= end]
    marquee = None                                               # og:image + spotlight
    for p in ORDER:
        for (y,d,l) in wk["promos"].get(p, []):
            if "Full show" in l: marquee = (p,y,d,l); break
        if marquee: break
    if not marquee and shows: marquee = (shows[0][0], shows[0][3][0][0], shows[0][2], shows[0][3][0][2])
    is_current = (wk is WEEKS[0])
    return dict(start=start, end=end, present=present, shows=shows,
                nclips=nclips, ples=ples, marquee=marquee, is_current=is_current,
                range_str="%s to %s" % (start.strftime("%B %-d"), end.strftime("%B %-d, %Y")))
```

`present` filtered on real clips is what keeps the current (in-progress) week honest: on Monday `present == ["WWE"]`, and the page renders exactly the sections it has data for. This is the mechanism that makes the page compound without ever being thin or duplicative.

Use "next" = older week (deeper archive), "prev" = newer week, consistently. This binds the weekly series into one crawl path and concentrates topical authority.

The compounding model: `WEEKS[0].promos` gains a show's clips each night (Mon Raw → Sat Collision). Make that visibly and structurally grow the page while every state (Monday-thin through Saturday-full) stays index-worthy and unique.

1. **Data-gated sections** — every H2 row, results block and JSON-LD node is generated from `m["present"]`/`m["shows"]`. 3. **"Still to come this week"** (current week only) makes the Monday page substantial before most clips exist: it lists the un-aired shows with air dates and how-to-watch links. It shrinks as the week fills and vanishes by Saturday. This is unique, time-sensitive content, not filler.

4. **Results & recaps block = the anti-thin engine.** Add an optional `results` field to the WEEKS model, per show, filled in as each show airs:

def week_meta(wk):
    start = wk["start"]; end = start + datetime.timedelta(days=6)
    present = [p for p in ORDER if wk["promos"].get(p)]
    shows = []
    for p in present:
        byshow = {}
        for (y,d,l) in wk["promos"][p]:
            byshow.setdefault((l.split("·")[0].strip(), d), []).append((y,d,l))
        for (s,d), clips in byshow.items():
            shows.append((p, s, d, clips))
    shows.sort(key=lambda t: t[2])
    nclips = sum(len(v) for v in wk["promos"].values())
    ples = [(dt,co,ev,note) for dt,(co,ev,note) in SPECIALS.items() if start <= dt <= end]
    marquee = None
    for p in ORDER:
        for (y,d,l) in wk["promos"].get(p, []):
            if "Full show" in l: marquee = (p,y,d,l); break
        if marquee: break
    if not marquee and shows: marquee = (shows[0][0], shows[0][3][0][0], shows[0][2], shows[0][3][0][2])
    return dict(start=start, end=end, present=present, shows=shows, nclips=nclips,
                ples=ples, marquee=marquee, is_current=(wk is WEEKS[0]),
                range_str="%s to %s" % (start.strftime("%B %-d"), end.strftime("%B %-d, %Y")))
