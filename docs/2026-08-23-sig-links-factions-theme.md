## What changed and why

### 1. Signature Matches are links now, with a hover preview
Each `.sig2-card` that has a real match page became an `<a class="sig2-card--link">`.
Hover or keyboard-focus opens a 320px preview panel: title, star rating, event /
date / venue, and a one-line hook.

**The trap worth remembering:** `.sig2-reel` is `overflow-x:auto`, which makes it a
scroll container. A scroll container *clips* its descendants — that is not a
paint-order problem, so no `z-index`, no `transform`, no `position:absolute` can
get a child panel out of it. The fix is to leave the subtree entirely: **one**
`.sig-prev` node is appended to `<body>` and positioned `fixed` from the hovered
card's `getBoundingClientRect()`. One node per page, not one per card.

Second trap, found while writing the event handlers: closing on
`mouseover of anything that is not a card` looks equivalent to closing on
`mouseout` and is not. Any scroll under a stationary cursor — the reel scrolling,
a `.reveal` transition settling — retargets the pointer and fires `mouseover` on a
neighbour, which tore the panel down one frame after it opened. Closing is
strictly `mouseout`'s job, and even there we trust geometry over the event: if
`clientX/clientY` is still inside the card's box, it is a retarget, not a
departure — reposition and stay open.

Content is baked into `data-sp-*` at build time from the target match page.
Hovering fetches nothing.

Coverage: cm-punk 2/8, john-cena 3/8, aj-styles 6/6. The rest have no match page
to link to yet — see Next steps.

### 4. Theme song
`js/theme-song.js` puts a playable Spotify embed at the top of the profile,
inside `#walkout`, before section 01. It is lazy — an `IntersectionObserver`
with a 240px rootMargin builds the iframe — and it never autoplays.

Graceful degradation: the module creates the real embed, then adjudicates
reachability at 4 seconds. If Spotify is blocked (adblocker, corporate network,
this build sandbox), the iframe is replaced with a three-row link panel —
Spotify / Apple Music / YouTube — and a theme-lineage rail beside it. Nothing
about the section depends on the embed rendering.

### 5. Faction prose measure — and the fix that did not work first
The faction pages inherited `.wrap` (1200px) with no measure of their own. The
deck line and the lead callout set at ~130 characters per line while
`.moment-body` under them sat at `68ch`. Three right edges on one column.

First attempt put `max-width:68ch` on each element. **It did not work**, and the
reason is worth keeping: `ch` resolves against *each element's own font-size*.
`.answer` sets at `--fs-500`, `.moment-body` at body size, so "the same 68ch"
came out 926px and 720px — two different right edges, which is the defect and not
the fix. A measure that is meant to be shared has to be one value:
`--fac-measure:720px` on `main.wl-faction`, applied to all three.

Verified at 1440px: lead, callout and body all span 120 → 840.

### 6. A real bug fixed
`js/profile.js` threw on every page with no `.idn` element — which is every
faction page. Added a guard.

## Decisions made and rejected

- **Rejected:** an `absolute`-positioned preview inside the card. Cannot work;
  see the clipping note above.
- **Rejected:** one `.sig-prev` node per card. Same result, N× the DOM.
- **Rejected:** fetching preview content on hover. Baking it into `data-sp-*` at
  build time costs nothing at runtime and cannot fail offline.
- **Rejected:** autoplaying the theme song. It is an entrance theme, not an
  ambush.
- **Rejected:** `68ch` as a shared measure. See above — it is not shared.
